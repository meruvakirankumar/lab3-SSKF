# Custom Agents - Code Architecture Analyzer

Custom agents for specialized development tasks within the Code Architecture Analyzer project.

---

## Agent: `backend-analyzer`

**Purpose:** Specialize in Python FastAPI backend development, code analysis pipeline, and API endpoint implementation.

**Expertise Focus:**
- Python code analysis and parsing logic
- FastAPI routing and request handling
- Mermaid diagram generation
- OpenAI/OpenRouter API integration
- Couchbase client setup

**Activation Triggers:**
- Modifying analysis pipeline (`_scan_codebase`, `_extract_imports`, `_store_analysis`)
- Adding new API endpoints
- Implementing new diagram types
- Working with `services/python-fast-api/src/`

**Customizations:**
```yaml
applyTo:
  - "services/python-fast-api/**"
  - "models/python/**"
  - "clients/python/**"
excludePatterns:
  - "**/__pycache__/**"
  - "**.pyc"
```

**Instructions:**
1. Reference [design-spec.md](design-spec.md) for functional requirements
2. Maintain regex-based parsing consistency across `_extract_imports` and `_extract_exports`
3. Always add graceful fallback when calling OpenAI APIs
4. Update `PROJECTS_DB`, `DIAGRAMS_DB`, `DATAFLOWS_DB` atomically to prevent race conditions
5. Log analysis milestones with timing (scan_ms, store_ms, total_ms)
6. Test with files 200KB-1MB to verify streaming and timeout behavior

**Expertise Focus:**

**Activation Triggers:**

**Customizations:**
```yaml
applyTo:

  - "clients/typescript/**"
excludePatterns:
  - "**/node_modules/**"
  - "**/dist/**"
  - "**.css"
```

**Instructions:**
1. Reference React Router config for API proxy: proxy `http://localhost:51732` → `http://localhost:3030`
2. Type all API responses and project/diagram/dataflow data structures
3. Use shadcn/ui components (Button, Card, Badge, Tabs) for consistency
4. Mermaid rendering: Always provide error boundary and fallback text display
5. Status polling: Use project status (`pending|analyzing|complete|failed`) to update diagrams
6. Responsive: Test layouts on 320px (mobile) and 1920px (desktop) viewports

## Agent: `ai-integration`

**Purpose:** Specialize in OpenAI/OpenRouter API calls, prompt engineering, and AI-enhanced analysis.

**Expertise Focus:**
- API authentication and routing (OpenRouter vs. OpenAI)
- Prompt design for architecture analysis
- JSON response parsing and fallback handling
- API error handling and retry logic
- Azure OpenAI configuration

**Activation Triggers:**
- Modifying `_get_openai_analysis()` function
- Adjusting prompts or analysis requests
- Handling API errors or timeouts
- Integrating Azure parameters

**Customizations:**
```yaml
applyTo:
  - "services/python-fast-api/src/routes/base.py" # _get_openai_analysis
  - "config/openapi-key.env"
```

**Instructions:**
1. Check key prefix: `sk-or-` → OpenRouter, `sk-` → OpenAI
2. Always include Azure deployment and API version in payload if configured
3. Use request timeout: `(OPENAI_CONNECT_TIMEOUT_SECONDS, OPENAI_TIMEOUT_SECONDS)` = `(2, 5)` seconds
4. Catch and log `RequestException`, `JSONDecodeError`, and HTTP errors (401, 403, 500)
5. Set global `OPENAI_DISABLED = True` on auth failure to prevent repeated requests
6. Prompt should request JSON-only response to ease parsing
7. Test with 10-50 files initially; production limit is 120 files
8. Log successful analysis completions for monitoring

## Agent: `api-integrator`

**Purpose:** Specialize in API endpoint design, request/response handling, and FastAPI patterns.

**Expertise Focus:**
- FastAPI routing and dependency injection
- File upload handling (multipart/form-data)
- Error responses and status codes
- Request validation
- CORS and middleware configuration

**Activation Triggers:**
- Adding new API routes
- Modifying upload logic
- Changing response formats
- Working with HTTPException or validation

**Customizations:**
```yaml
applyTo:
  - "services/python-fast-api/src/routes/**"
  - "services/python-fast-api/src/conf/**"
```

**Instructions:**
1. All responses follow: `{"success": true/false, "data": {...}, "error": "..."}`
2. File uploads use `UploadFile` from FastAPI; stream to disk to avoid memory bloat
3. Validate project_name on upload (non-empty, sanitized)
4. Return 404 if project_id not in `PROJECTS_DB`
5. Return 400 for invalid requests (missing fields, wrong file type)
6. Set status transitions atomically: `pending` → `analyzing` → `complete`/`failed`
7. Include `upload_timestamp` in ISO 8601 format for all project responses
8. CORS is open (`allow_origins=["*"]`) for workshop scope; restrict in production

## Agent: `polytope-expert`

**Purpose:** Specialize in Polytope framework configuration, service orchestration, and environment setup.

**Expertise Focus:**
- Polytope YAML configuration (`polytope.yml`)
- Service lifecycle and dependency management
- Environment variable injection
- Config/values/secrets loading
- Multi-service coordination

**Activation Triggers:**
- Modifying `polytope.yml` configurations
- Adding services or dependencies
- Changing environment variable setup
- Troubleshooting service startup

**Customizations:**
```yaml
applyTo:
  - "**/polytope.yml"
  - "config/**"
  - ".instructions.md"
```

**Instructions:**
1. Services are defined in `services/*/polytope.yml`
2. Top-level `polytope.yml` includes all services via `include:` directive
3. Port mappings: FastAPI (3030), React (51732), Couchbase (8091, 8092, 8093, 11210, 11211)
4. Environment variables come from `config/values.yml` and `config/secrets.yml`
5. Secrets prefixed with `pt.secret` are sensitive and should not be logged
6. Test service startup: `pt run service:python-fast-api`
7. Verify mounts in polytope.yml (e.g., `/clients/python`, `/models/python`, `/config`)
